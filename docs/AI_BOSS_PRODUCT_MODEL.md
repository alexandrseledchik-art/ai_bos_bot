# Продуктовая модель AI-BOSS v0.1

Дата: 04.05.2026

Статус: рабочая продуктовая модель. Документ отвечает на вопрос: какую самостоятельную ценность создаёт AI-BOSS и как он связан с консалтингом Александра.

## 1. Главная продуктовая роль

AI-BOSS - не только вход в консультацию.

Он является самостоятельным продуктом, который помогает собственнику:

- вынести бизнес из головы;
- описать текущую ситуацию;
- отделить симптом от причины;
- увидеть срез зрелости;
- получить рабочую гипотезу ограничения;
- понять, почему выбрана именно она;
- выбрать первый проверочный шаг;
- подобрать инструмент;
- сохранить кейс в Кабинете AI-BOSS.

Консультация с Александром усиливает продукт, но не является обязательным финалом и не должна быть главным смыслом AI-BOSS.

Главная продуктовая рамка:

> AI-BOSS должен стать самостоятельной управляющей функцией любого бизнеса: видеть контекст, держать память, находить ограничения, выбирать следующий шаг, запускать работу с инструментами и возвращаться к результату.

## 2. Две роли AI-BOSS

### 2.1. Для внешнего пользователя

AI-BOSS ведёт управленческий кейс:

> запрос -> сигналы -> диагностика -> гипотеза -> следующий шаг -> инструмент -> артефакт -> проверка результата.

Ценность без консультации:

- ясность по текущей ситуации;
- первичная карта слабых областей;
- рабочая версия главного ограничения;
- первый шаг без распыления.

### 2.2. Для бизнеса Александра

AI-BOSS является CEO-слоем:

- упаковывает сам консалтинг;
- готовит решения собственнику;
- анализирует качество диалогов;
- собирает повторяющиеся ошибки;
- помогает строить продуктовую линейку;
- готовит консультационные кейсы;
- возвращает результаты консультаций в систему.

## 3. Продуктовый маршрут

Базовый маршрут:

1. Пользователь пишет в Telegram.
2. AI-BOSS понимает тип входа: симптом, сайт, инструмент, общий вопрос.
3. AI-BOSS собирает первые сигналы.
4. Пользователь переходит в Кабинет AI-BOSS.
5. Заполняет профиль.
6. Проходит экспресс-диагностику.
7. Видит матрицу зрелости.
8. Видит рабочую гипотезу ограничения.
9. Получает следующий шаг.
10. Открывает инструмент или создаёт/обновляет артефакт.
11. Продолжает кейс с AI-BOSS: проверяет действие, обновляет данные, возвращается к результату.
12. При необходимости идёт на разбор с экспертом как на дополнительное усиление.
13. После консультации результат возвращается в систему и продолжает жить как часть кейса.

### 3.1. Маршрут внешнего пользователя по инструментам

Следующий продуктовый слой - сопровождение внешних пользователей по программе инструментов.

AI-BOSS должен уметь:

- зарегистрировать пользователя и создать личный кабинет;
- вести его по архитектуре бизнеса слой за слоем;
- предлагать следующий инструмент в правильной последовательности;
- давать личную копию Google-шаблона для заполнения;
- помогать заполнять инструмент прямо в чате, если так удобнее;
- сохранять ответы, ссылки на документы, snapshots и observations;
- использовать накопленную информацию как актуальный контекст в следующих ответах.

Ключевое правило:

> Инструмент - это не просто ссылка. Это управленческий шаг, который AI-BOSS объясняет, сопровождает, сохраняет и связывает с общей памятью компании.

Детальная спецификация: `docs/EXTERNAL_USER_TOOL_WORKFLOW_SPEC.md`.

## 4. Что должно быть понятно пользователю

Пользователь не обязан понимать “11 слоёв”.

Он должен понимать:

- что AI-BOSS помогает не гадать, что чинить первым;
- что слабая область не всегда является главной причиной;
- что гипотеза - это рабочая версия, которую нужно проверить;
- что следующий шаг нужен для снижения неопределённости;
- что Кабинет хранит кейс и не даёт потерять выводы.

## 5. Что не должно происходить

AI-BOSS не должен:

- звучать как обычный AI-советчик;
- продавать консультацию слишком рано;
- раскрывать внутреннюю механику без запроса;
- превращать диагностику в анкету;
- выдавать инструменты раньше понимания ограничения;
- обещать финальный диагноз без фактов.

## 6. Продуктовые артефакты

Минимальный набор:

- профиль компании;
- текущий запрос;
- экспресс-диагностика;
- матрица зрелости;
- общий вывод по диагностике;
- гипотеза ограничения;
- объяснение выбора гипотезы;
- следующий шаг;
- рекомендованные инструменты;
- рабочий артефакт;
- консультационное резюме как дополнительный артефакт, если пользователь выбирает разбор с Александром;
- артефакт после консультации, если консультация состоялась.

## 6.1. CEO-контур в Кабинете

Следующий продуктовый слой - не новый совет, а панель управления кейсом.

CEO-контур показывает:

- готов ли профиль;
- насколько заполнена диагностика;
- есть ли рабочая гипотеза ограничения;
- есть ли следующий шаг в работе;
- какие решения нужно вынести собственнику;
- какие действия AI-BOSS может готовить сам;
- какие открытые петли контроля мешают двигаться дальше.

Это первый практический переход от “AI-BOSS понимает себя как CEO-слой” к “AI-BOSS фактически держит управленческую повестку”.

Граница:

- AI-BOSS готовит повестку, варианты решений и следующий шаг;
- собственник утверждает стратегические развилки;
- система не делает вид, что автономно управляет бизнесом без фактов, полномочий и интеграций.

## 7. Первый продуктовый эксперимент

Эксперимент:

> Провести 10-20 альфа-кейсов через маршрут: Telegram -> Mini App -> гипотеза ограничения -> следующий шаг -> инструмент/артефакт -> optional консультация.

Что проверяем:

- понимает ли пользователь ценность AI-BOSS;
- проходит ли он диагностику;
- понятна ли гипотеза ограничения;
- принимает ли пользователь следующий шаг;
- создаётся ли полезный артефакт без обязательной консультации;
- возникает ли желание перейти к разбору только там, где это действительно усиливает кейс;
- помогает ли резюме не начинать консультацию с нуля, если пользователь выбрал консультацию.
