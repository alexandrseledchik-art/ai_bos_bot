# AI-BOSS alpha pilot

Дата фиксации: 14.08.2026.

Цель пилота — проверить полезность Telegram-first управленческого цикла на реальных компаниях до расширения функциональности.

## Кого приглашаем

Основная группа — 10–15 собственников или CEO, у которых бизнес вырос быстрее системы управления:

- есть команда и действующие процессы;
- собственник остаётся узким местом или не видит единой картины;
- рост усиливает хаос, разрывы ответственности или недоверие к данным;
- есть реальная управленческая ситуация, которую можно проверить действием.

Дополнительная группа — до 5 читателей книги. Это отдельный канал входа, а не отдельный коммерческий сегмент.

## Два входных маршрута

### Собственник или CEO

```text
Telegram
→ описание ситуации
→ факты и конкурирующие гипотезы
→ рабочая версия ограничения
→ один проверочный шаг
→ «фиксируем»
→ действие
→ «результат: ...»
```

### Читатель книги

```text
QR в книге
→ веб-платформа с инструментами
→ регистрация через Telegram
→ постоянная кнопка возврата на платформу
→ применение одного инструмента к реальной ситуации
→ продолжение управленческого кейса в Telegram
```

## Что считаем завершённым кейсом

Кейс засчитывается, если сохранены:

1. роль, размер, стадия, состояние и текущая задача без смешения осей;
2. минимум два наблюдаемых факта;
3. рабочая гипотеза, явно отделённая от фактов;
4. один проверочный шаг;
5. решение пользователя — зафиксировано или отклонено;
6. для принятого шага — ответственный, срок и ожидаемый результат;
7. фактический результат или зафиксированная причина незавершения;
8. короткий итоговый артефакт кейса.

## Метрики

- время до первого полезного шага;
- доля кейсов с подтверждённым пересечением сегмента;
- доля кейсов с рабочей гипотезой;
- доля предложений, дошедших до «фиксируем»;
- доля зафиксированных решений с фактическим результатом;
- число лишних или повторных вопросов;
- доля ответов, которые пользователь счёл конкретными и применимыми;
- доля кейсов, где понадобился инструмент, платформа или экспертный разбор;
- ошибки маршрутизации между диагностикой, инструментом и обычным ответом.

## Как измеряем в текущем продукте

Новый кабинет для пилота не нужен. В существующей админке `/admin` есть раздел «Пилот», который собирает показатели из уже сохранённых данных:

- источник входа из `/start <source>`;
- путь канала и квалифицированный сегмент из `thread.entry_state`;
- факты, гипотезы, первый шаг и артефакты из сущностей активного кейса;
- команды «фиксируем» и «результат: ...» из рабочего диалога;
- время от создания диалога до первого сохранённого шага;
- последнюю оценку качества evaluator.

Книжный маршрут передаёт источник через платформу и затем в Telegram-команде. Ссылка со страницы книги:

```text
https://aiboss.seledchik.ru/app?utm_source=book&utm_medium=book_page&utm_campaign=book_tools
```

Для QR-точки используется `utm_medium=qr`. Платформа преобразует эти метки в `/start book` или `/start book_qr`. Атрибуция сохраняется даже в режиме предварительного одобрения доступа, но не меняет приветствие или продуктовый сценарий.

## Контроль качества

После каждого кейса:

1. открыть диалог в `/admin`;
2. запустить evaluator;
3. отметить первое место, где бот потерял смысл или доверие;
4. классифицировать проблему: prompt, routing, memory, skill, данные или продуктовый маршрут;
5. исправлять повторяющуюся проблему только после двух и более подтверждений;
6. добавлять регрессионный кейс перед изменением production-логики.

## Что не строим во время пилота

- новую Telegram Mini App;
- автономных агентов на каждый скилл;
- большой универсальный кабинет;
- новые интеграции без подтверждённого кейса;
- дополнительные платные продукты до понимания первого результата.

Веб-платформа остаётся дополнительным рабочим пространством для инструментов, сохранённых результатов и возврата из Telegram. Основной живой диалог и управленческий цикл остаются в Telegram.

## Следующая разработка после первых кейсов

При достаточном спросе на применение инструментов следующим исполняемым маршрутом становится:

```text
architecture_navigation
→ tool_selection
→ tool_facilitation
```

После подтверждения команды «фиксируем» усиливается action ownership:

- ответственный;
- срок;
- критерий результата;
- контрольная точка;
- фактический результат;
- learning event при расхождении гипотезы и факта.

## Решения, которые пилот должен дать

1. Какой измеримый первый результат AI-BOSS обещает собственнику без участия Александра.
2. Как называется первый платный формат.
3. Какой итоговый артефакт пользователь получает после закрытого цикла.
4. В какой момент платформа усиливает кейс, а в какой создаёт лишний переход.
5. Когда нужен разбор с Александром.
