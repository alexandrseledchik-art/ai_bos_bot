# Синтетический alpha-пилот AI-BOSS — 16 августа 2026

## Формат

Пилот проведён без реальных пользователей и без записи тестовых диалогов в production Telegram. В изолированном хранилище смоделированы 15 участников с многоходовыми диалогами: собственники и CEO на разных стадиях, книжные входы, запрос конкретного инструмента, отказ от первой гипотезы и экспертная продуктовая задача.

Для 13 диагностических сценариев проверялся полный цикл: факты → рабочая гипотеза → первый шаг → «фиксируем» → выполнение → фактический результат.

## Результаты

Офлайн-регресс после исправлений:

- 15/15 сценариев прошли контракт;
- 13/13 управленческих циклов закрылись результатом;
- 9/9 ожидаемых приоритетных сегментов распознаны;
- 3/3 книжных маршрута сохранили канал book;
- 0 ответов с несколькими вопросами;
- 0 утечек внутренних полей.

Первый полный живой прогон через `gpt-5.4-mini`:

- 12/15 чистых PASS;
- 11/13 управленческих циклов закрылись;
- 9/9 сегментов и 3/3 книжных маршрута распознаны;
- 0 внутренних технических утечек;
- 0 повторяющихся начал содержательных ответов;
- найдено три воспроизводимых дефекта.

После исправлений все три проблемных сценария повторно прогнаны через живую модель и прошли 3/3 со score 100/100. Таким образом, все 15 сценариев имеют успешный живой результат: 12 из полного прогона и 3 из контрольного повторного прогона после исправлений.

## Что обнаружено и исправлено

1. Контекст конкретного инструмента RACI мог потеряться после уточняющего ответа пользователя и перейти в общую диагностику. Теперь инструментальный маршрут сохраняется по состоянию скилла и последней содержательной реплике.

2. Сегментация не распознавала конструкции вроде «среднего производственного бизнеса», «среднего IT-бизнеса», «на стадии роста», часть data-gap сигналов и эксперта без явно названной отрасли. Правила расширены и закреплены тестами.

3. После отказа пользователя от первой гипотезы новый диагностический цикл мог требовать лишние факты. Накопленные измеримые сигналы теперь учитываются во всём кейсе.

4. Живая модель могла сформулировать гипотезу и шаг, но не выставить технический флаг action wave. Содержательное решение теперь нормализуется в ожидающее подтверждения решение, а приглашение «фиксируем / не фиксируем» формулируется живо.

5. Вопрос модели мог ошибочно превратиться в зафиксированный шаг. Action wave больше не создаётся из вопросительной формулировки.

6. До создания активного кейса автономный сборщик мог прочитать факты другого бизнеса из общего состояния. Контекст теперь жёстко ограничен активным case/company; добавлен отдельный тест на межклиентскую изоляцию.

7. Evaluator требовал приглашение в платформу внутри диалога, хотя продуктово переход закреплён в постоянном меню Telegram. Устаревшая проверка удалена. Закрытие цикла фактическим результатом больше не штрафуется за отсутствие искусственного следующего вопроса.

## Проверки

- Skill architecture: 25 контрактов;
- Skill selection: 35/35;
- Diagnostic skill pilot: 20/20;
- persistent skill runs: пройдено;
- audience, admin analytics, core E2E: пройдено;
- site navigator и web platform: пройдено;
- автономная изоляция данных компаний: пройдено.

## Ограничение результата

Это сильный синтетический preflight, но не замена пилоту с реальными людьми. Следующий этап должен проверить непредсказуемые формулировки, доверие, понятность команды «фиксируем» и фактическую готовность собственника выполнить предложенный шаг.
